# 回答の使い方

要件シートの回答を、全体像の HTML のどの節のどの判断に使うかの一覧。質問を足したり変えたりしたときは、この表を合わせて直す。

## 回答と節の対応

| 質問 | 使う節 | 使い方 |
|------|-----------|--------|
| Q1-1 決めたいこと | 画面のイメージ・テーブルの構成・構成 | 画面のイメージと mart 層の集計の単位を決める。構成では主要ワークロードの判断に使う |
| Q1-2 見る人 | 構成・テーブルの構成 | 人数を BI の利用者数に使う。部署ごとに閲覧のロールを分け、ロールごとに読めるテーブルを決める |
| Q1-3 分析の種類 | 画面のイメージ・テーブルの構成・構成 | 画面のイメージのグラフと表の種類、mart 層の集計の単位を決める。予測とグルーピングは ML のワークロードとして扱う。「AIチャット」は自然言語で問い合わせるワークロードとして扱う |
| Q1-4 今の数値の出し方 | 次にやること | Q2 にないシステムやファイルが出てきたら次にやることに回す |
| Q1-5 困っていること | 画面のイメージ | 解消する課題として、画面のイメージの上部に1文で書く |
| Q2 システムの種類・主なデータ | テーブルの構成 | 取り込み層のテーブルを決める |
| Q2 置き場所・取り出し方・件数・更新のタイミング | 構成 | 取り込み方式・データ量・連携頻度の判断に使う |
| Q2 出力される範囲 | テーブルの構成・構成 | 整形層の更新方法と取り込み方式を決める |
| Q2 DB の製品・変わった行を見分ける列 | 構成 | 取り込みの製品が DB の製品に対応するかと、差分を取り出せるかの判断に使う。列が「ない」ならすべての行を取り出す |
| Q2 データの単位 | テーブルの構成 | 目標などを MART の集計の単位にそろえる方法を決める。単位が MART より粗いときは割り振る方法を次にやることに回す |
| Q2 管理部署 | 次にやること | そのソースに関する次にやることの決める人にする |
| Q3-1〜Q3-4 | 構成 | 「要件への当て方」の表のとおり |
| Q4-3 集計の作り方 | 構成 | 「SQL を書いて作りたい」なら変換は SQL で書くツール（DWH の機能か dbt など）にする。「画面で操作して作りたい」なら画面で操作して作れるツールにする。「未定」なら次にやることに回す |
| Q4-1・Q4-2・Q4-4〜Q4-8 | 構成 | 「要件への当て方」と「セキュリティの点検」の表のとおり |
| 全質問の空欄と「不明」 | 次にやること | 推測で埋めずに次にやることに回す。Q4-7 と Q4-8 の表の空欄は、使っていない・検討していないと読み、次にやることに回さない |
| 回答どうしの食い違い | 次にやること | 鮮度と更新のタイミングが合わないなど、回答どうしが食い違うときは次にやることに回す |

## テーブルの構成の決め方

| 層 | 決め方 |
|----|--------|
| 取り込み | Q2 の1行につき1テーブル |
| 整形 | Q2 の出力される範囲が「毎回すべてのデータ」なら洗い替え、「変わった分だけ」なら差分を反映する。「不明」なら次にやることに回す |
| mart | Q1-1 と Q1-3 から決めた集計の単位で作り、Q1-1 に出てくる指標と軸を列にする |

## 要件への当て方

構成で確認する要件の項目と、それに使う回答。

| 要件の項目 | 使う回答 |
|-----------|---------|
| データ量と増加見込み | Q2 の件数・Q3-3 の遡る期間 |
| 連携頻度とリアルタイム性 | Q3-1 の鮮度・Q3-2 の見る頻度・Q3-4 の見たい時刻・Q2 の更新のタイミング |
| クラウド前提と既存資産 | Q4-1 のクラウド・Q4-2 の BI・Q4-7 の DWH・データ基盤製品・Q4-8 のデータ連携・変換ツール・Q2 の置き場所 |
| コスト制約・運用体制 | Q1-2 の見る人・Q4-3 の集計の作り方 |
| 主要ワークロード | Q1-1 の決めたいこと・Q1-3 の分析の種類 |
| セキュリティ要件 | Q4-4 の個人情報・Q4-5 の接続できる場所の制限 |
| 取り込み方式 | Q2 の置き場所・取り出し方・出力される範囲・Q3-1 の鮮度 |

## セキュリティの点検

観点ごとに回答を当て、使う製品の機能は公式ドキュメントで確かめる。判断に使える回答がない観点は次にやることに回す。

| 観点 | 使う回答 | 構成に書く内容 |
|------|---------|--------------------------|
| 個人情報の保護 | Q4-4 | マスキングと行アクセス制御の要否・個人情報を置く層 |
| 閉域接続 | Q4-5・Q4-6 | Q4-5 は利用者と BI ツールが DWH に接続するときの制限で、「社内のネットワークからだけ許す」なら IP 制限、「閉域網からだけ許す」なら閉域接続の機能を使う。Q4-6 は社内の DB からデータを取り出すときの経路で、「ない」なら経路を用意する工程を足す |
| 認証と権限 | Q1-2 | 利用者の区分から決めるロールの階層・秘密情報を持たない認証方式 |
| 監査 | Q4-4 | 監査ログの保管期間と保管先 |

## 取り込みと読み込みの選び方

実行ごとに構成が変わらないように、取り込みと読み込みは次の 2 段で決める。まず回答から方式を決め、次に決まった順番で製品を選ぶ。

### 方式を決める

ソース（Q2 の 1 行）ごとに、上から順に当てはまる行を使う。

| 条件 | 方式 |
|------|------|
| 取り出し方が「手作業でしか出せない」 | 人がファイルを置き、置いたファイルを読み込む |
| 鮮度（Q3-1）が「ほぼリアルタイム」か「数時間前まで」で、DB に直接接続できる | 変更データキャプチャ（CDC）で変わった行を続けて取り出す |
| 取り出し方が API | 1 日 1 回、API から取り出す |
| 取り出し方が「ファイルを自動で出力できる」 | 1 日 1 回、出力されたファイルを読み込む |
| DB に直接接続でき、出力される範囲が「変わった分だけ」で、変わった行を見分ける列がある | 1 日 1 回、前回からの差分を取り出す |
| DB に直接接続でき、上の行に当てはまらない | 1 日 1 回、すべての行を取り出す |
| 取り出し方が「不明」 | 方式を決めずに次にやることに回す |

方式が CDC なら、ファイルが届くたびに読み込む。それ以外の方式では、取り出しが終わったあとに 1 日 1 回読み込み、続けて変換を動かす。

### 製品を選ぶ

製品名はサービスの追加や名前の変更で変わるため、このファイルには書かない。方式ごとに、実行した日の公式ドキュメントで次の順に探し、最初に要件を満たしたものを選ぶ。

1. DWH が自分で持っている取り込みの機能（コネクタ・ファイルの自動読み込み・定期実行の仕組み）
2. DWH と同じクラウドのマネージドサービス
3. 1 と 2 で足りないときだけ、短いコードを定期実行する仕組み

要件を満たすとは、回答に書かれた状態のまま動くことを指す。元のシステムに回答にない条件（DB で変更追跡を有効にする、主キーを足すなど）が要る製品は要件を満たさないものとして次の段に進み、その製品は「選ばなかった案」に要る条件を添えて書く。

DWH は Q4-7 の「契約・利用中」、なければ「導入を検討中」、どちらもなければ Q4-1 のクラウドで決める。探し方と確かめ方は architecture-sources-guide.md に従い、選んだ製品と選んだ順番の段（1〜3 のどれか）を「この構成を選んだ理由」に書く。
